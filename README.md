# 돌봄기기 통합 모니터링 서버

돌봄 대상자에게 설치된 **다섯 종류의 기기**에서 생체·재실·활동 데이터를 모아,
실시간 관제 화면 · 날짜별 리포트 · 이상 알림을 제공하는 서버.

여러 실증 현장에서 24시간 가동할 수 있도록 구성돼 있다 (Jetson 계열 장비, systemd).

```
[침대 매트] [레이더] [천장 레이더] [압력 센서] [손목 워치]
      └──────────┴────── 수집 ──────┴──────────┘
                         │
              [FastAPI + 분석 캐시]
                         │
      ┌──────────────────┼──────────────────┐
  관제 대시보드      CSV 리포트         디스코드 알림
```

---

## 지원 기기

| 종류 | 무엇을 보는가 | 수신 방식 |
|---|---|---|
| **EMFIT QS** | 침대 매트 — 심박 · 호흡 · 움직임 · 수면 단계 | 기기가 30초마다 POST |
| **AI Radar** (라닉스 RMR602A) | 침대 위 자세 — 누움 · 앉음 · 걸터앉음 · **낙상** | 기기가 1~50초마다 POST |
| **McKare** (VSR22 / AI 110) | 천장·벽 레이더 — 구간 재실 · 체온 · 열화상 | 기기가 POST |
| **돌봄기기 사용감지** (ESP32 FSR) | 압력 센서 — 기기를 실제로 쓰고 있는가 · 배터리 | 사용 시작/종료 때만 POST |
| **Garmin 워치** | 안정시 심박 · 걸음(또는 휠체어 밀기) · 수면 단계 | **서버가 클라우드에서 30분마다 당겨옴** |

> 마지막 한 줄이 다른 넷과 결정적으로 다르다. 워치는 폰을 거쳐 Garmin 클라우드까지만 가고
> 서버로 직접 보내지 못해서, 수집기가 주기적으로 당겨온다. 그래서 **수 시간 지연이 정상**이다.

## 주요 기능

- **실시간 관제 대시보드** — 기기 종류별 구역, 15초 자동 갱신. 이상한 것이 위로 정렬된다
- **배정 이력** — "이 기기를 그때 누가 썼는가"를 기간별로 기록한다. 기기를 다른 사람에게
  옮겨도 과거 데이터가 섞이지 않는다
- **리포트** — 날짜·사용자별 CSV / 기간 ZIP. 기기 종류마다 파일을 나눠 뽑는다
- **디스코드 알림** — 연결 끊김 · 배터리 부족 · 토큰 만료. 시설별 채널로 나눠 보낼 수 있고,
  봇 명령어(`/현황` `/상세보기` `/배터리` `/시설이름`)로 언제든 조회할 수 있다
- **NRCarec 연동** — 레이더가 낙상·걸터앉음을 감지하면 간호 앱으로 푸시
- **권한 3단계** — 관리자 로그인 / 시설 단위 URL / 개인 URL

## 설계에서 지키는 원칙

이 저장소의 코드는 아래 판단을 반복해서 따른다. 고칠 때도 깨지 않는 것이 좋다.

1. **조용한 것을 근거로 경고하지 않는다.** "신호가 없다"는 고장일 수도, 안 쓰는 중일 수도 있다.
   기기가 직접 이상을 알려주거나, 시간 기준이 성립하는 종류에서만 알림을 만든다.
2. **거짓 알림 쪽으로 새지 않는다.** 끊김을 감지해도 한 번 더 지켜보고(디바운스), 전송에
   성공했을 때만 알림 상태를 저장한다.
3. **기기 종류를 SN 모양으로 추측하지 않는다.** 등록 정보에 종류를 명시한다
   (ESP32 MAC과 레이더 SN이 똑같이 12자리 16진수라 실제로 겪은 문제다).
4. **사람이 손댄 데이터를 코드가 지우지 않는다.** 이름·위치를 고친 흔적이 있으면 자동 정리에서 뺀다.
5. **모르는 것은 모른다고 표시한다.** 데이터가 없을 때 '정상'으로 보이게 만들지 않는다.

## 구조

```
app.py            FastAPI — 수신 경로 · 대시보드 · 리포트 · 알림 · 관리 화면
analyzer.py       파싱 · 캐시 · 배정 이력 · 리포트 생성
*_parser.py       기기 종류별 payload 해석 (radar / mckare / fsr / garmin)
garmin_poller.py  Garmin 클라우드 수집기 (systemd timer 로 주기 실행)
discord_bot.py    디스코드 슬래시 명령어 봇 (별도 프로세스)
nrcarec_alert.py  낙상 경보 외부 전송 (Firestore + FCM)
*_data.jsonl      기기 종류별 수집 로그 (append-only, 커밋하지 않음)
```

기기 종류를 하나 추가할 때 건드리는 곳은 **파서 하나 + `analyzer._process_line` 한 줄 +
카드 렌더러 하나**로 정리돼 있다. 실제 사례는 [docs/garmin_integration_design.md](docs/garmin_integration_design.md) 참고.

## 실행

```bash
python3 -m venv venv && source venv/bin/activate
pip install fastapi uvicorn pandas requests pytz
pip install firebase-admin                          # NRCarec 낙상 경보용
pip install "discord.py"                            # 디스코드 봇용
pip install "garminconnect==0.2.38" "garth>=0.5.17,<0.6.0"   # Garmin 수집기용

uvicorn app:app --host 0.0.0.0 --port 8080
```

운영 주소와 관리자 계정은 소스에 적지 않고 환경변수로 설정한다:

```bash
export EMFIT_EXTERNAL_BASE="https://monitoring.example.com"
export EMFIT_ADMIN_USER="admin"
```

실제 호스트·계정·대상자·기기 식별자는 공개 문서나 코드 예시에 넣지 않는다.

> `python app.py` 로 직접 띄우면 포트 80을 쓴다. 운영은 systemd 가 uvicorn 8080 으로 띄운다.
> 최초 기동 시 로그 전체를 파싱하느라 30초~수 분이 걸리고, 그동안에도 **센서 수신은 계속된다.**

배포 절차(복사 → 앱 멈추지 않고 검사 → 통과할 때만 재시작)는 [MANUAL.md](MANUAL.md) §6.7 참고.

## ⚠️ 데이터 취급

**이 서버가 다루는 것은 실제 대상자의 건강 데이터다.**

- 수집 로그(`*_data.jsonl`) · 리포트 CSV · 인증 토큰 · 비밀번호 파일은 **커밋하지 않는다.**
  새 파일을 만들면 같은 커밋에서 [.gitignore](.gitignore) 에 먼저 추가한다.
- 조회 화면은 로그인·토큰으로 막혀 있지만, **센서 수신 경로에는 인증이 없다.**
  HTTPS 미적용 상태이며, 알려진 제한사항은 [MANUAL.md](MANUAL.md) §9 에 정리돼 있다.
