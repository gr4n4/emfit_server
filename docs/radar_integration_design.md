# RANIX RMR602A 레이더 통합 설계안 (Emfit QS 대시보드)

> 목적: 기존 Emfit QS 대시보드에 RANIX 레이더(RMR602A)를 **함께** 띄운다.
> 표시 방침: **둘 다** — HR/RR 바이탈은 Emfit처럼, 거기에 자세/낙상을 추가 표시.
> 상태: **설계만** (코드 미반영). 검토 후 구현.

---

## 0. 한 줄 요약

지금 서버는 "Emfit 말만 알아듣는 안내데스크"다. 건물(대시보드·카드·그래프·인증·배정 이력)은
그대로 두고, **RANIX 통역사 한 명**만 `analyzer._process_line`에 붙이면 된다.
입구(`POST /`)는 손대지 않아도 된다 (JSON이면 뭐든 받아 저장 중).

---

## 1. 두 기기 데이터 비교

| 의미 | Emfit QS | RANIX BED 모델 | RANIX FALL 모델 |
|------|----------|----------------|-----------------|
| 기기 식별자 | `device` (SN, 6 hex) | `MAC` (12 hex) | `macAddress` (12 hex) |
| 심박수 | `heart_rate` | `HR` | ❌ 없음 |
| 호흡수 | `respiration_rate` | `BR` | ❌ 없음 |
| 활동/자세 | `activity` (0~32767 숫자) | `POS` (0~6 범주) | `pose` (2/4/5) |
| 낙상 | ❌ 없음 | `POS=4` | `pose=4` |
| 신호건강 | Status API(별도) | `ERR` (0정상/1신호없음) | (없음) |
| 사람 수 | — | — | `pnum` |
| 좌표 | — | — | `p1_x1`... |
| **타임스탬프** | `date_occurred` (unix) | ❌ **없음** | ❌ **없음** |
| 전송 형식 | `data` 배열로 감쌈 | **평평한 JSON** | **평평한 JSON** |
| 전송 주기 | 30초 | 누움 5초 / 그외 자세변경시·50초 | 1초 |

### ⚠️ 먼저 확정해야 할 것 (구현 전 체크)
1. ~~**레이더가 BED 모델이냐 FALL 모델이냐?**~~ → **✅ 확정: BED 모델.**
   - 실기기에서 바이탈(HR/BR) + 자세 + 낙상이 모두 나옴을 사용자가 확인 (2026-06-16).
   - 따라서 카드의 ❤️HR 🫁RR 슬롯을 그대로 채울 수 있고, POS로 자세/낙상 표시.
   - FALL 모델·좌표(pX_y) 분기는 당장 불필요 (추후 필요 시 추가).
2. **타임스탬프 없음**: 레이더 payload엔 시각이 없다. → 서버 수신시각(`server_received_at`)을
   측정 시각으로 쓴다. Emfit과 달리 "기기가 찍은 시각"이 아니라 "서버가 받은 시각" 기준.
3. **POS=-1**: 예시에 등장. 사람 미감지/무효값으로 보임 → 부재 처리.

## 2. POS / pose 값 → 대시보드 상태 매핑

| POS | 의미 | 대시보드 상태 | 카드색/아이콘 |
|-----|------|----------------|----------------|
| 0 | 누움 | 재실 🛌 | 파랑 |
| 1 | 앉음 | 재실 (앉음) | 파랑 |
| 2 | 배회 | 재실 (배회) | 파랑/주의 |
| 3 | 걸터앉음 | 재실 (걸터앉음) | 파랑 |
| 4 | **낙상** | **🚨 낙상** | **빨강 강조** |
| 5 | 자리비움 | 부재 🛏️ | 회갈색 |
| 6 | 뒤척임 | 재실 (뒤척임) | 파랑 |
| -1 | (미감지) | 부재/대기 | 회색 |
| ERR=1 | 레이더 신호없음 | 끊김 🔴 | 빨강 |

> Emfit의 기존 3분류(재실/부재/끊김)에 **낙상**을 1개 더 얹는 형태.
> 카드 UI는 거의 그대로, 상태 판정 함수만 기기 타입별 분기.

## 3. 변경 포인트 (파일·함수 단위)

### 3-1. `analyzer.py` — 핵심 (번역기)

**(a) `_process_line(line, storage)` 에 RANIX 분기 추가**
- 위치: 기존 `status_at` 분기와 `data` 분기 사이.
- 판별: `"MAC" in row and "POS" in row` (BED) / `"macAddress" in row and "pose" in row` (FALL).
- 처리:
  ```
  sn   = row["MAC"]                       # 식별자
  ts   = server_received_at → unix 변환    # 레이더는 자체 시각 없음
  pos  = int(row["POS"])
  add_to_storage(storage, sn, ts, "Radar", {
      "심박수(HR)": _num(row.get("HR")),    # "0" → 0, 문자열 정리
      "호흡수(RR)": _num(row.get("BR")),
      "자세(POS)": pos,                     # ★ 새 필드
      "낙상": pos == 4,
      "활동량(ACT)": None,                  # 레이더엔 ACT 숫자 없음
      "상태설명": "레이더측정"
  })
  ```
- 주의: 레이더 값은 모두 **문자열**("0", "92")로 옴 → 숫자 변환 헬퍼 필요.
- `ERR=="1"` 이면 신호없음 → 별도 상태 플래그 저장(끊김 처리용).

**(b) 기기 타입 구분**
- `DEVICE_INFO[sn]`에 `"type": "radar"` 또는 `"emfit"` 필드 추가 (기본 emfit).
- 카드 렌더링에서 이 type으로 분기.

**(c) `get_device_statuses()` / 연결상태**
- Emfit은 Status API 하트비트로 connected 판정.
- 레이더는 별도 하트비트 없음 → **최근 수신 시각 + ERR**로 파생:
  - 최근 N초(예: 120초) 내 수신 + ERR=0 → 연결됨
  - 그 이상 무신호 → 끊김

### 3-2. `app.py` — 표시(UI)

**(a) `_render_card(sn, info, state, ds, now, token)`**
- `info["type"] == "radar"` 분기 추가.
- 상태 판정: 기존 `absent = act < 1` 대신 `자세(POS)` 기반.
  - POS=4 → 낙상 카드(빨강 + 🚨), 최상단 정렬.
  - POS=5/-1 → 부재.
  - 그 외 → 재실(+ 자세 라벨 표시).
- HR/RR 슬롯: 그대로 사용 (BED 모델이면 값 있음).
- ACT 슬롯: 숫자 대신 **자세 라벨**(누움/앉음/배회…) 표시.

**(b) `_card_sort_key(...)`**
- 낙상(POS=4)을 끊김보다도 위(최우선)로 올리는 우선순위 추가.

**(c) 상세 페이지 / 시계열 (`/api/device/{sn}/timeseries`)**
- HR/RR 그래프는 공용 재사용 가능.
- 자세(POS)는 시간축 위 색띠(누움/앉음/낙상…) 형태로 추가 표시 — 별도 블록.
- `DEFAULT_BLOCK_ORDER = ["summary","hr","rr","act"]` 에 `"posture"` 블록 추가 검토.

**(d) `POST /` (입구)**
- **변경 없음.** 이미 JSON이면 그대로 받아 저장 중.
- 단, 레이더 설정에서 전송 주소를 운영 서버(`https://monitoring.example.com` 등)로 지정해야 함.
  (RANIX 문서 HTTP API의 `ssid/pw`는 레이더의 AP/네트워크 설정용)

### 3-3. 기기 등록 (`/devices`)
- 레이더 MAC을 기기로 등록 (이름/위치/그룹 + type=radar).
- 배정 이력(assignments) 시스템은 SN 키 기반이라 MAC을 SN처럼 그대로 사용 가능.

## 4. 영향 없는 부분 (그대로 둠)
- 인증/세션/토큰(device·view)·로그인 — 무관.
- 배정 이력(assignments) 로직 — MAC을 SN으로 쓰면 그대로 동작.
- 의견(feedback)·환경설정(preferences)·리포트 다운로드 — 무관.
- 점검(워밍업) 게이트 — 무관 (단, POST / 는 점검 중에도 수신하므로 레이더 데이터 유실 없음).
