# 젯슨 배포 가이드 — v3.5.0 (돌봄기기 사용감지 센서)

> 윈도우 PC 의 코드를 젯슨 실서버에 올리는 절차.
> **핵심 안전장치: 파일을 덮어써도 재시작 전까지는 기존 앱이 그대로 돈다.**
> "복사 → (앱 멈추지 않고) 검사 → 통과할 때만 재시작" 순서로 간다.
> 검사에서 걸리면 재시작을 안 하므로 Emfit·Radar 는 계속 살아있다.

## 올리는 파일 (3개)
| 파일 | 젯슨에서 | 왜 |
|---|---|---|
| `app.py` | 교체 | `/jy01` 수신 경로, 사용감지 대시보드 섹션 |
| `analyzer.py` | 교체 | FSR 저장·기기 종류(kind) 분류·자동 등록 |
| `fsr_parser.py` | **신규** | 사용감지 payload 해석. analyzer 가 import 함 |

> ⚠️ 셋은 한 세트다. `analyzer.py` 만 올리고 `fsr_parser.py` 를 빠뜨리면
> import 실패로 앱이 안 켜진다. 반드시 3개 같이 올린다.

## 값
| 항목 | 값 |
|---|---|
| 젯슨 | `operator@jetson-host` |
| 앱 경로 | `/opt/monitoring_server/` |
| 서비스 | `emfit` (systemd, 포트 8080) |
| 배포 전 버전 | 3.4.1 → **배포 후 3.5.0** |
| 새 기기 SN | `ECE334450058` (ESP32 MAC) |

## 0단계. 젯슨 현재 파일 백업 (되돌리기 안전장치)

```bash
ssh operator@jetson-host

mkdir -p ~/backup/pre_350
cp ~/emfit_server/app.py         ~/backup/pre_350/
cp ~/emfit_server/analyzer.py    ~/backup/pre_350/
cp ~/emfit_server/assignments.json ~/backup/pre_350/   # 기기 목록도 백업
ls -l ~/backup/pre_350/
grep '^VERSION' ~/backup/pre_350/app.py   # VERSION = "3.4.1" 확인
```
> `fsr_parser.py` 는 젯슨에 아직 없으니 백업 대상 아님.
> ⚠️ `assignments.json` 도 백업하는 이유 — 3.5.0 이 처음 켜질 때 사용감지 기기를
> 자동으로 한 줄 추가한다. 되돌릴 때 이 파일도 같이 되돌려야 깔끔하다.

SSH 는 **켜둔 채로** 두고, 1단계는 **윈도우 PowerShell** 에서 한다.

## 1단계. 윈도우 → 젯슨 파일 복사 (PowerShell)

새 PowerShell 창에서 (SSH 창 말고):
```powershell
scp -O "C:\path\to\monitoring_server\app.py" "C:\path\to\monitoring_server\analyzer.py" "C:\path\to\monitoring_server\fsr_parser.py" operator@jetson-host:/opt/monitoring_server/
```
비밀번호 입력하면 3개 파일이 전송된다.

---

## 2단계. 젯슨에서 검사 (앱 아직 안 건드림)

다시 SSH 창으로 — **재시작 전에** 새 코드가 멀쩡한지 먼저 본다.
별도 파이썬 프로세스라 돌고 있는 앱에는 영향이 없다:
```bash
cd ~/emfit_server

# (1) 3개 파일 다 왔는지 + 버전 확인
ls -l app.py analyzer.py fsr_parser.py
grep '^VERSION' app.py            # VERSION = "3.5.0" 이어야 함

# (2) 문법 + import 검사 — 앱을 켜지 않고 확인
python3 -c "import ast; [ast.parse(open(f,encoding='utf-8').read()) for f in ['app.py','analyzer.py','fsr_parser.py']]; print('문법 OK')"
python3 -c "import fsr_parser; print('fsr_parser import OK')"
```
**둘 다 OK 가 떠야만** 다음 단계로 간다.
→ 에러가 나면 **재시작하지 말고** 곧장 [되돌리기]로. 앱은 아직 3.4.1 로 잘 돌고 있다.

---

## 3단계. 서비스 재시작 & 확인

```bash
sudo systemctl restart emfit

sleep 5
systemctl is-active emfit          # active 여야 함
```
`active` 가 아니면 로그를 본다:
```bash
sudo journalctl -u emfit --no-pager | tail -30
```
→ 에러 있으면 [되돌리기]로.

`active` 면 앱 응답 확인:
```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/dashboard   # 401 또는 200 = 정상
```

> 참고: 재시작 직후에는 86MB 로그 전체를 다시 읽느라 몇 분간 "점검 중" 화면이 뜬다.
> 그동안에도 센서 데이터 수신(`/`, `/radar`, `/mckare`, `/jy01`)은 계속 받으므로 유실은 없다.

## 4단계. 기존 기기 회귀 확인 (가장 중요)

배포로 기존 Emfit·Radar 가 깨지면 안 된다:
```bash
tail -f ~/emfit_server/emfit_data.jsonl     # 새 줄 찍히면 정상, Ctrl+C 로 종료
```

대시보드에서 확인:
- [ ] EMFIT QS 카드가 **그대로 5대** 보이고 통신 시각이 갱신됨

- [ ] 헤더 요약이 `N / M 연결됨 · EMFIT n대 · Radar n대 · 사용감지 1대` 형태

## 5단계. /jy01 수신 테스트 (보드 없이 더미로)

ESP32 실물 없이도 젯슨 자신에서 더미를 쏴서 확인한다:
```bash
# 사용 시작
curl -s -X POST http://localhost:8080/jy01 \
  -H "Content-Type: application/json" \
  -d '{"deviceId":"EC:E3:34:45:00:58","event":"press","uptime_ms":123456,"battery_mv":3850,"battery_pct":62,"duration_ms":0}'
# → {"status":"success","source":"fsr","device":"EC:E3:34:45:00:58"}

# 사용 종료 (3분 사용했다고 가정)
curl -s -X POST http://localhost:8080/jy01 \
  -H "Content-Type: application/json" \
  -d '{"deviceId":"EC:E3:34:45:00:58","event":"release","battery_pct":62,"duration_ms":180000}'

# 전용 파일이 생겼는지 확인
tail -2 ~/emfit_server/fsr_data.jsonl
```
대시보드에 "🔘 돌봄기기 사용 감지" 섹션이 뜨고,
카드가 **사용 중 → 미사용(직전 사용 시간 3분)** 으로 바뀌면 성공.

> 이 더미 2건은 테스트용이라 원하면 지운다 (실물 붙이기 전 정리):
> `sed -i '/ECE334450058\|EC:E3:34:45:00:58/d' ~/emfit_server/fsr_data.jsonl`
> 그다음 `sudo systemctl restart emfit`

## 6단계. 실물 ESP32 연결 후

```bash
# 보드가 실제로 보내는 deviceId 확인
tail -5 ~/emfit_server/fsr_data.jsonl

# 자동 등록 로그 확인 (등록 안 된 ID 로 왔을 때만 찍힘)
sudo journalctl -u emfit --no-pager | grep "FSR 기기 자동 등록"
```

**보드의 MAC 이 `ECE334450058` 이 아니었다면?**
자동 등록되어 `돌봄기기 ECE3344500XX` 같은 이름으로 뜬다. 데이터는 안 잃는다.
`/devices` 화면에서 이름·설치장소를 실제 값으로 고치면 끝.

> ⚠️ ESP32 는 베이스 MAC 하나에서 여러 개를 파생시킨다.
> WiFi STA = 베이스 / softAP = 베이스+1 / 블루투스 = 베이스+2.
> 서버로 POST 하는 건 STA 이므로 보드에서 `WiFi.macAddress()` 값을 쓴다.

**쓰지 않는 기본 등록을 지우고 싶다면** — `/devices` 에서는 삭제가 안 되므로
`assignments.json` 에서 해당 줄을 지우고 재시작한다.

