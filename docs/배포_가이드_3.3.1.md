# 젯슨 배포 가이드 — v3.3.1 (AI Radar)

> 윈도우 PC 의 코드를 젯슨 실서버에 올리는 절차.
> **핵심 안전장치: 파일을 덮어써도 재시작 전까지는 기존 앱이 그대로 돈다.**
> 그래서 "복사 → (앱 멈추지 않고) 검사 → 통과할 때만 재시작" 순서로 간다.
> 검사에서 걸리면 재시작을 안 하므로 Emfit 은 계속 살아있다.

## 올리는 파일 (3개)
| 파일 | 젯슨에서 | 왜 |
|---|---|---|
| `app.py` | 교체 | /radar 엔드포인트, 대시보드 2섹션, CSV 분리 |
| `analyzer.py` | 교체 | BED/FALL 병합, 로그 파일 분리 |
| `radar_parser.py` | **신규** | 레이더 payload 해석. analyzer 가 import 함 |

> ⚠️ 셋은 한 세트다. `analyzer.py` 만 올리고 `radar_parser.py` 를 빠뜨리면
> import 실패로 앱이 안 켜진다. 반드시 3개 같이 올린다.

## 값
| 항목 | 값 |
|---|---|
| 젯슨 | `operator@jetson-host` |
| 앱 경로 | `/opt/monitoring_server/` |
| 서비스 | `emfit` (systemd, 포트 8080) |
| 배포 전 버전 | 3.2.2 → **배포 후 3.3.1** |

---

## 0단계. 젯슨 현재 파일 백업 (되돌리기 안전장치)

젯슨 SSH 접속 후, 지금 도는 3.2.2 파일을 백업해 둔다:
```bash
ssh operator@jetson-host

mkdir -p ~/backup/pre_331
cp ~/emfit_server/app.py      ~/backup/pre_331/
cp ~/emfit_server/analyzer.py ~/backup/pre_331/
ls -l ~/backup/pre_331/          # app.py, analyzer.py 두 개 있으면 OK
grep '^VERSION' ~/backup/pre_331/app.py   # VERSION = "3.2.2" 확인
```
> radar_parser.py 는 젯슨에 아직 없으니 백업 대상 아님.

여기서 SSH 는 **켜둔 채로** 두고, 아래 1단계는 **윈도우 PowerShell** 에서 한다.

---

## 1단계. 윈도우 → 젯슨 파일 복사 (PowerShell)

새 PowerShell 창에서 (SSH 창 말고):
```powershell
scp -O "C:\path\to\monitoring_server\app.py" "C:\path\to\monitoring_server\analyzer.py" "C:\path\to\monitoring_server\radar_parser.py" operator@jetson-host:/opt/monitoring_server/
```
비밀번호 입력하면 3개 파일이 전송된다.
> `-O` 는 지난번처럼 구형 복사 방식 강제 (없으면 경로 오류 날 수 있음).

---

## 2단계. 젯슨에서 검사 (앱 아직 안 건드림)

다시 SSH 창으로 돌아와서 — **재시작 전에** 새 코드가 멀쩡한지 먼저 본다.
지금 이 검사는 별도 파이썬 프로세스라, 돌고 있는 앱에는 영향이 없다:
```bash
cd ~/emfit_server

# (1) 3개 파일 다 왔는지 + 버전 확인
ls -l app.py analyzer.py radar_parser.py
grep '^VERSION' app.py            # VERSION = "3.3.1" 이어야 함

# (2) 문법 + import 검사 — 앱을 켜지 않고 확인
python3 -c "import ast; [ast.parse(open(f,encoding='utf-8').read()) for f in ['app.py','analyzer.py','radar_parser.py']]; print('문법 OK')"
python3 -c "import radar_parser; print('radar_parser import OK')"
```
**둘 다 OK 가 떠야만** 다음 단계로 간다.
→ 만약 여기서 에러가 나면? **재시작하지 말고** 곧장 [되돌리기]로. 앱은 아직 3.2.2 로 잘 돌고 있다.

---

## 3단계. 서비스 재시작 & 확인

검사 통과했으면 새 코드로 재시작:
```bash
sudo systemctl restart emfit

# 5초쯤 기다렸다가 상태 확인
sleep 5
systemctl is-active emfit          # active 여야 함
```
`active` 가 아니면 로그를 본다:
```bash
sudo journalctl -u emfit --no-pager | tail -30
```
→ 에러 있으면 [되돌리기]로.

`active` 면 앱 응답 확인:
```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/dashboard   # 401 또는 200 = 정상
```

## 4단계. Emfit 계속 잘 들어오는지 (회귀 확인)

배포로 기존 Emfit 이 깨지면 안 된다:
```bash
tail -f ~/emfit_server/emfit_data.jsonl     # 새 줄 찍히면 정상, Ctrl+C 로 종료
```
대시보드( https://... 아직이면 http://monitoring.example.com/dashboard )에서
기존 Emfit 카드 5대가 그대로 보이고 통신 시각이 갱신되면 OK.

## 5단계. /radar 수신 테스트 (레이더 없이 더미로)

레이더 실물 없이도, 젯슨 자신에서 더미를 쏴서 엔드포인트가 받는지 본다:
```bash
# BED 형식 예시
curl -s -X POST http://localhost:8080/radar \
  -H "Content-Type: application/json" \
  -d '{"MAC":"A1B2C3D4E5F6","POS":"0","BR":"14","HR":"62","ERR":"0"}'
# → {"status":"success","source":"ai_radar","model":"bed"} 나오면 성공

# FALL 형식 예시
curl -s -X POST http://localhost:8080/radar \
  -H "Content-Type: application/json" \
  -d '{"name":"rmr602a","macAddress":"A1B2C3D4E5F6","pose":"2","pnum":"1"}'
# → {"status":"success","source":"ai_radar","model":"fall"}

# 레이더 전용 파일이 생겼는지 + 내용 확인
tail -2 ~/emfit_server/radar_data.jsonl
```
대시보드에 "📡 AI Radar" 섹션이 뜨고 카드가 보이면 완료.
> 이 더미 2건은 테스트용이라, 원하면 지워도 된다:
> `sed -i '/A1B2C3D4E5F6/d' ~/emfit_server/radar_data.jsonl` (레이더 실물 붙이기 전 정리)

## 되돌리기 (2단계 검사 실패 or 재시작 후 문제)

백업으로 되돌리고 재시작하면 3.2.2 로 복구된다:
```bash
cp ~/backup/pre_331/app.py      ~/emfit_server/app.py
cp ~/backup/pre_331/analyzer.py ~/emfit_server/analyzer.py
rm -f ~/emfit_server/radar_parser.py     # 새로 올린 파일 제거
sudo systemctl restart emfit
systemctl is-active emfit                 # active 확인
grep '^VERSION' ~/emfit_server/app.py     # 3.2.2 로 돌아왔는지
```
